The link in a reminder (Me)

One URL field, so it holds the source. The notes carry an excerpt, the source name, #source, and a talaria://item/<id> link that opens the item in Talaria with its why, decisions and trail. The context store already records a URL for most sources.

How Hermes emits a card

Two ways, both plain text in the reply so every other client still sees something sensible.

FormWhat Hermes writesWhat Talaria does
A link to something that existsthe entity's URL on its own line: https://github.com/nsainaney/talaria/issues/12, talaria://task/t_3f9a, talaria://reminder/<id>, or context://kanban:card:default:t_3f9aUnfurls it into the card from the context store (issue, card) or EventKit (reminder), and keeps it live. A link inside a sentence becomes a pill. Other clients see the link.

  Retry with the refreshed token in SpeakrClient.upload; …

for a reminder: due: 2026-10-01, time: 09:00 (optional), list: Admin, url: …, tags: [mail]		Renders a dashed proposed card. The one strong action creates it: Proceed files the card and sets it ready; Add to Reminders writes it with EventKit; for an issue, Create opens it on GitHub. Edit opens the fields. Other clients see the YAML, which is readable.

Fields are the entity's own: an issue has repo, number, state, labels, assignee; a task has id, status, assignee, board, parents, run; a reminder has list, due, time, completed, url, notes. Talaria never invents state: the card always reads back from the store, so a wrong field in the YAML shows up as a difference, not as a fact.

Talaria needs a bearer-authenticated listener for the context engine on the WireGuard address (nix-config work); the kanban is reached through the dashboard it already signs into. The Apple bridge on titan stays read-only; Talaria writes Reminders itself.
